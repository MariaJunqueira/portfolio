From 30 to 72: practical Angular performance wins

Maria Junqueira·October 2026·Performance·8 min read

On one product I worked on, the Lighthouse performance score sat at 30. A few months later it was 72. There was no rewrite and no new framework, just a list of unglamorous fixes done in the right order. Here's that list.

Every app is different, and your numbers will be too. The order matters more than the exact techniques: measure, fix the biggest thing, measure again.

Measure before you touch anything

I started with three tools: Lighthouse for a repeatable score, the Chrome Performance panel to see what the main thread was actually doing, and a bundle analyser (source-map-explorer on a production build) to see what we were shipping.

ng build --configuration production --source-map
npx source-map-explorer dist/**/*.js

The bundle view is usually the wake-up call. You find a date library with every locale, a charting package loaded on the login page, or a whole admin module downloaded by every visitor.

1. Lazy-load routes

The biggest single win was making sure people only downloaded the code for the page they were on. Feature areas moved behind lazy routes:

export const routes: Routes = [
  { path: '', loadComponent: () => import('./home/home.component').then(m => m.HomeComponent) },
  { path: 'account', loadChildren: () => import('./account/routes').then(m => m.ACCOUNT_ROUTES) },
  { path: 'admin', canMatch: [isAdmin], loadChildren: () => import('./admin/routes').then(m => m.ADMIN_ROUTES) },
];

Note canMatch on the admin route: users who can't access it never download it at all.

2. Calm down change detection

Angular's default change detection checks every component on every event. In big component trees, that adds up. The fixes were simple but needed discipline:

  • OnPush everywhere it's safe. Components re-render only when their inputs change or an observable they use emits.
  • trackBy on every list (or track in the new control flow), so Angular reuses DOM nodes instead of rebuilding them.
  • No function calls in templates. {{ total(items) }} runs on every check. A pure pipe or a precomputed value runs once.
  • The async pipe instead of manual subscriptions, which also removed a few memory leaks.
@Component({
  selector: 'app-location-list',
  changeDetection: ChangeDetectionStrategy.OnPush,
  template: `
    @for (loc of locations$ | async; track loc.id) {
      <app-location-card [location]="loc" />
    }
  `,
})
export class LocationListComponent {
  locations$ = inject(LocationService).locations$;
}

3. Fix images (it's always images)

Images were the heaviest thing on most pages. We served modern formats, gave every image explicit dimensions to stop layout shifts, sized them for the device, and lazy-loaded anything below the fold. Angular's NgOptimizedImage directive makes most of this the default:

<img ngSrc="hero.webp" width="1200" height="600" priority />
<img ngSrc="card.webp" width="400" height="300" />  <!-- lazy by default -->

4. Get out of the way of first paint

  • Reduced render-blocking resources: deferring non-critical scripts, inlining what the first screen needs, and loading fonts with font-display: swap.
  • Served static assets from a CDN with long cache headers and hashed filenames, so returning visitors download almost nothing.

These changes helped SEO as much as speed. Together with proper meta tags and structured data, the SEO score went above 90.

5. Lock it in with budgets

Performance work fades unless something stops regressions. Angular's build budgets fail the build when a bundle grows past a limit:

"budgets": [
  { "type": "initial", "maximumWarning": "500kb", "maximumError": "800kb" },
  { "type": "anyComponentStyle", "maximumWarning": "6kb" }
]

A failing build starts a conversation at the right moment: before the slow code ships, not after users feel it.

The boring truth

None of this is clever. The 40-point jump came from doing the obvious things consistently and measuring after each one. If you only do one thing this week, run a bundle analyser on your production build. I promise you'll find something.
